# Day03 真题考点精讲 · 软件工程与数据工程

> Day03 ｜ 主题：软件工程（需求→设计→测试→维护、CMMI）＋数据工程（数据治理、数据仓库、数据挖掘） ｜ 对应教程"软件工程"与"数据工程"章节

## 一、今天在考纲中的位置

高项综合知识中，软件工程与数据工程板块合计稳定占 15-20 题，是信息化知识部分题量最大的一块，也是案例题"开发过程找茬"与"测试计算"的直接出处。本部分知识体系庞大，但考法极其模式化——开发模型选型、内聚耦合排序、测试层级顺序、数据仓库四大特性，全是"背准即得分"的固定靶。已备考过系规管的你，今天会感到大量概念似曾相识，但注意：高项侧重"过程与模型的选择判断"，不是编程细节。今日另有 Day01-02 滚动复习题 16 道进入模拟卷。

## 二、核心考点精讲

### 考点 1：软件生命周期（一切的起点）

**考点**：软件生存周期的阶段划分与各阶段任务。
**考法**：阶段定位题——"某活动属于哪个阶段""解决'做什么/怎么做'的阶段是"。
**速记**：**可行性研究与项目开发计划 → 需求分析 → 概要设计 → 详细设计 → 编码 → 测试 → 维护**。
- 口诀："**分析管做什么（逻辑模型），设计管怎么做（物理模型），编码管做出来，测试管挑毛病，维护管用得久**"；
- 概要设计＝模块划分＋模块间接口（软件结构）；详细设计＝模块内部算法＋数据结构（编码的直接依据）；
- **维护是生命周期中持续时间最长、花费成本最高的阶段**（约占软件总成本的一半以上）——高频判断题。

### 考点 2：开发模型五巨头（每年必考 3-5 题）

**考点**：瀑布、原型、螺旋、增量、敏捷（含 Scrum/XP）的特征与适用场景。
**考法**：场景选模型——给一段项目特征描述，问应采用哪种模型；给模型问特点。
**速记表（背熟这张表，本考点 90% 到手）**：

| 模型 | 一句话定位 | 适用场景 | 高频陷阱 |
|------|-----------|---------|---------|
| 瀑布 | 文档驱动、阶段顺序严格、逐级下落 | 需求明确且稳定 | "需求易变的项目选瀑布"是典型错误项 |
| 原型 | 快速构造可运行原型，让用户"看到再说" | 需求模糊、难以事先定义 | 原型≠最终产品，用途是澄清需求 |
| 螺旋 | 瀑布＋原型＋**风险分析**，迭代一圈一风险 | 大型、复杂、高风险项目 | **风险驱动**是螺旋模型的独有标签 |
| 增量 | 第一个增量即可运行，逐步增加功能 | 核心需求早明确、需尽早交付 | 增量≠原型：增量交付的是真功能 |
| 敏捷 | 小步快跑、拥抱变化、可工作的软件高于文档 | 需求快速变化、小团队 | 敏捷宣言四组价值观"响应变化**高于**遵循计划" |

- 螺旋模型每一迭代周期：**制定计划（定目标）→ 风险分析 → 实施工程 → 客户评估**，四活动循环；
- **Scrum 三角色**：产品负责人（管 Product Backlog 优先级）、Scrum Master（护流程、清障碍，不是领导）、开发团队；三仪式：冲刺（Sprint，2-4 周）、每日站会（15 分钟时间盒）、冲刺评审与回顾；
- **XP 极限编程**招牌实践：结对编程、测试驱动开发（TDD）、持续集成、小版本发布——给实践选方法。

### 考点 3：需求工程（案例找茬的常驻考点）

**考点**：需求工程四过程、需求分类、结构化分析与 UML。
**考法**：排序题（四过程顺序）；功能/非功能需求辨析；给图选名字（DFD/用例图）。
**速记**：
- **需求工程四步：需求获取 → 需求分析 → 需求定义（规格说明）→ 需求确认（验证）**——顺序固定，考排序；
- **功能需求**（系统"做什么"：支付、导出）vs **非功能需求**（"做得多好"：性能 3 秒响应、可靠性、安全性、易用性）——给一条需求判类型是送分题；
- **结构化分析（SA）两大工具：数据流图（DFD）＋数据字典（DD）**，共同构成系统逻辑模型；DFD 的要素：数据流、加工（处理）、数据存储、外部实体；
- **UML 是面向对象的统一建模语言**：静态图——用例图（功能视图）、类图、对象图、构件图、部署图；动态图——顺序图（消息按时间序）、状态图、活动图、协作图；"描述参与者与系统交互"＝用例图。

### 考点 4：软件设计原则——内聚与耦合（必考 1-2 题）

**考点**：模块独立性、七级内聚、六级耦合的排序。
**考法**：排序比较（最高内聚/最低耦合）；给模块关系描述判耦合类型。
**速记**："**设计追求高内聚、低耦合**——模块内部抱团紧、模块之间牵连少。"
- **内聚（模块内部）从低到高**：偶然 → 逻辑 → 时间 → 过程 → 通信 → 顺序 → **功能内聚（最高，最好）**；
- **耦合（模块之间）从低到高**：非直接 → **数据耦合（传递简单参数，最低可用）** → 标记 → 控制 → 公共 → **内容耦合（直接改人家内部，最差）**；
- 经典题面："两模块仅通过参数传递简单数据"＝数据耦合；"一模块直接访问另一模块内部数据"＝内容耦合；
- 配套原则：**信息隐蔽**（Parnas）——模块内部信息对不需要它的模块不可见；模块分解要"单入口单出口、功能单一可预测"。

### 考点 5：软件测试（本板块题量之王，4-6 题）

**考点**：V 模型、白盒/黑盒、逻辑覆盖分级、四层测试顺序、α/β 测试。
**考法**：V 模型对应关系；覆盖标准强弱排序；给方法归类（白盒还是黑盒）。
**速记**：
- **测试四层顺序（铁律）：单元 → 集成 → 系统 → 验收**；
- **V 模型对应关系**（左开发右测试，一一挂钩）：需求分析↔**验收测试**；概要设计↔**集成测试**；详细设计↔**单元测试**；
- **测试目的**：尽可能多地**发现缺陷**，而不是证明软件无缺陷；
- **白盒测试**（基于程序内部结构与逻辑）：用于**单元测试**为主；逻辑覆盖从弱到强：**语句覆盖（最弱）→ 判定覆盖 → 条件覆盖 → 判定/条件覆盖 → 条件组合覆盖 → 路径覆盖（最强）**；
- **黑盒测试**（基于功能规格，不看代码）：等价类划分、边界值分析、判定表、因果图、错误推测法——**边界值是对等价类划分的补充**；
- 集成测试两种策略：**自顶向下**（需要**桩模块** stub 代替下层）、**自底向上**（需要**驱动模块** driver 代替上层）；
- **α 测试**：开发方场所、用户参与；**β 测试**：用户实际使用环境、开发方不在场；
- 缺陷度量两公式（案例计算常客）：**缺陷密度＝缺陷总数÷代码规模（KLOC）**；**缺陷移除效率 DRE＝测试发现的缺陷÷（测试发现＋上线后遗留）**。

### 考点 6：软件维护与配置管理（滚动深化）

**考点**：四类维护、结构化维护、基线。
**考法**：维护类型场景判断（Day01 已考，此处深化）；基线的定义与作用。
**速记**：
- 四类维护再巩固：**纠正性**（修缺陷）、**适应性**（适应环境/政策变化）、**完善性**（功能增强，**占比最大**）、**预防性**（提前除隐患）；
- **结构化维护 vs 非结构化维护**：有完整文档（需求、设计、测试文档齐备）的维护＝结构化维护，效率高、风险低——软件工程强调文档的根本原因；
- **基线**：配置项经过**正式评审和批准**后形成的版本，是后续变更控制的基准；**基线变更必须走变更控制流程**——这两句是标准答案原文。

### 考点 7：CMMI（成熟度模型，稳定 1-2 题）

**考点**：CMMI 五个成熟度等级、阶段式与连续式。
**考法**：等级名称排序；给能力描述判断等级。
**速记**：**一初始、二已管理、三已定义、四量化管理、五优化**。
- 口诀："**初始乱着干，二级管项目，三级有标准（组织级标准过程库），四级用数据，五级持续改**"；
- **阶段式表示法**关注组织整体**成熟度等级**（1-5）；**连续式表示法**关注各过程域的**能力等级**（0-3）——"关注组织成熟度的是阶段式"是固定考法；
- 达到三级（已定义）意味着：项目不是各自为政，而是**裁剪组织标准过程**执行；四级才是"量化管理"——三级≠量化管理，高频陷阱。

### 考点 8：数据工程（近年权重上升，5-8 题）

**考点**：数据治理、DCMM、数据仓库、OLAP、数据挖掘。
**考法**：概念定义题为主；数据仓库四大特性"选不属于"；OLAP 操作场景判断；数据挖掘方法归类。
**速记**：
- **数据治理**：对数据资产行使**权力和控制**的活动集合（规划、监督、执行），核心是把数据当作**受管理的企业资产**，强调**决策与问责**；数据治理定规则、数据管理做执行（治理 vs 管理的对照，与 Day02 的 IT 治理逻辑同构）；
- **DCMM**（我国《数据管理能力成熟度评估模型》国家标准）：**8 个能力域、5 个成熟度等级**（初始级、受管理级、稳健级、量化管理级、优化级）——"5 个等级"是数字类考法；
- **数据仓库四大特性（必背原文）**：**面向主题、集成的、相对稳定（非易失）、反映历史变化（时变）**——"面向事务、实时更新"是仓库没有的特性；
- 配套概念链：**ETL**（抽取-转换-加载，进仓库的必经之路）→ **ODS**（操作数据存储：面向主题、集成、**可更新**、存近期数据，支撑快速查询）→ **数据集市**（面向部门/特定主题的小仓库）；
- **OLTP vs OLAP**：OLTP 面向日常事务处理（增删改、响应快）；OLAP 面向分析决策（多维、聚合、扫描量大）；
- **OLAP 五操作**：**钻取**（汇总→明细，向下）、**上卷**（明细→汇总，向上）、切片、切块、旋转——"从汇总深入到明细"＝钻取；
- 多维模型：**星型模型**（事实表＋非规范化的维表，连接少查询快）vs **雪花模型**（维表再规范化拆分，冗余小、连接多）；
- **数据挖掘**：从大量数据中发现**隐含的、事先未知的、潜在有用的**知识；四大任务归类：**分类**（有预定义类别，决策树，有监督）、**聚类**（无预定义类别，K-Means，无监督）、**关联规则**（购物篮分析）、**预测/回归**；
- **元数据**＝描述数据的数据；**主数据**＝企业跨系统共享复用的核心业务实体数据（客户、产品、供应商）；**数据质量维度**：完整性、准确性、一致性、及时性、唯一性、有效性。

### 考点 9：滚动复习区（Day01-02 高频错题回炉）

- 信息化六要素定位词：应用是龙头、资源是核心、人才是关键、法规是保障；
- IaaS/PaaS/SaaS 场景判断：租虚机＝IaaS，租平台环境＝PaaS，租软件＝SaaS；
- 事件管理止血（尽快恢复）vs 问题管理治本（根因）；SLA 对客户、OLA 对内部、UC 对供应商；
- ITSS 四要素 PPTR（人员、过程、技术、资源）；维护类型中完善性占比最大；
- 项目三约束（范围-时间-成本）；强矩阵/项目型 PM 权力大，弱矩阵 PM 只是协调员。

## 三、今日考法规律总览（真题视角）

1. 开发模型全部是"场景选型"题：题干描述需求特征＋项目规模，答案对应模型标签，背速记表即可全对；
2. 测试考点的固定三板斧：V 模型对应关系、逻辑覆盖强弱排序、白盒/黑盒方法归类——年年换数字不换套路；
3. 数据工程以"定义原文"式命题为主：数据仓库四特性、数据挖掘三形容词、DCMM 的 8 域 5 级，精确记忆优于模糊理解；
4. 今日考点在案例中的形态：开发过程找茬（无需求文档、未评审、跳过集成测试）、测试指标计算（缺陷密度/DRE）、CMMI 应用分析。
