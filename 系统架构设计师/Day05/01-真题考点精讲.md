# Day05 真题考点精讲 · 数据库系统

> Day05 ｜ 主题：数据库三级模式与设计三阶段＋范式与模式分解＋事务与并发控制＋恢复技术＋分布式与 NoSQL ｜ 对应教程数据库系统相关章节

## 一、今天在考纲中的位置

数据库系统是综合知识选择题的传统得分高地：三级模式与数据独立性、范式判定、并发控制三兄弟（丢失修改/脏读/不可重复读）几乎年年出现；Day02 已铺垫的关系与范式概念今天将深入到**候选键求解与模式分解计算**——这是案例计算题的常客。分布式数据库（2PC/分片）、CAP/BASE 与 NoSQL 属于近年加重的新考点，也是论文"数据库架构设计"主题的直接弹药。

## 二、核心考点精讲

### 考点 1：三级模式结构与数据独立性（开篇必考）

**考点**：外模式/模式/内模式、两级映像。
**考法**：模式层次对应、独立性由哪个映像保证。
**速记**：
- 三级模式：**外模式**（用户视图）→**模式**（全局逻辑结构，唯一）→**内模式**（物理存储）；
- 两级映像：**外模式/模式映像**保证**逻辑独立性**（改模式不动应用）；**模式/内模式映像**保证**物理独立性**（换存储不动模式）；
- 一句话："改哪个层面，就由隔开它的那层映像来兜底独立性"。

### 考点 2：数据库设计三阶段与 ER 模型

**考点**：需求分析→概念设计→逻辑设计→物理设计→实施→运行的阶段序；ER 模型转换规则。
**考法**：阶段产物对应（概念设计产出 ER 图）、转换规则选择题。
**速记**：
- **概念设计**：ER 图，与具体 DBMS 无关；**逻辑设计**：ER→关系模式集合；**物理设计**：存储结构与索引；
- 转换规则：1:1 联系可并入任一端；1:n 联系并入 n 端；**m:n 联系必须转成独立关系模式，主键为两端实体键的组合**。

### 考点 3：函数依赖与候选键求解（计算题地基）

**考点**：完全/部分/传递函数依赖，候选键求法。
**考法**：给 FD 集求候选键（案例与选择题双考）。
**速记**：
- 完全依赖：X 整体才能决定 Y（任何真子集都不行）；部分依赖＝有真子集也能决定（2NF 的病灶）；传递依赖：X→Y→Z 且 Y↛X（3NF 的病灶）；
- **候选键求法三步**：① 只出现在 FD 右部、从未出现在左部的属性→不在候选键中；② 只出现在左部的属性→必在候选键中；③ 余下属性逐一组合试闭包，能推出全部属性的极小组合即候选键。
  例：R(A,B,C)，F＝{AB→C, C→B}：A 只在左部必在键中；试 AB：AB⁺＝ABC ✓、AC⁺＝ACB ✓ 且均可极小化——候选键为 **AB 与 AC**。

### 考点 4：范式体系 1NF→4NF（判定题的主产区）

**考点**：各级范式定义与给定模式的最高范式判定。
**考法**：给关系＋FD 判定"最高属于第几范式"。
**速记表**：

| 范式 | 要求 | 一句话病灶 |
|------|------|-----------|
| 1NF | 属性**原子不可再分** | "复合属性/多值单元格" |
| 2NF | 1NF＋**消除非主属性对键的部分依赖** | 组合键中"一半就能决定" |
| 3NF | 2NF＋**消除传递依赖** | 主键→A→B 的"二传手" |
| BCNF | 所有 FD 的**决定因素都是超键** | 决定因素不是键 |
| 4NF | 消除非平凡且非函数依赖的**多值依赖** | "一行对多行"的独立多值 |

- 判定流程：原子性？→部分依赖？→传递依赖？→决定因素？逐级降档；
- 高范式=冗余与操作异常更少，但**连接代价上升**——规范化程度是设计权衡而非越高越好。

### 考点 5：模式分解（无损连接与保持函数依赖）

**考点**：分解的两个质量标准。
**考法**：二元分解无损判定、特性归属判断。
**速记**：
- **无损连接**：分解后自然连接不丢不冒信息。二元分解充分条件：**R1∩R2 → R1−R2 或 R1∩R2 → R2−R1**；
- **保持函数依赖**：F 在各模式上投影的并集能**逻辑蕴含全部原依赖**；
- 结论（选择/案例双考）：**3NF 分解总能做到无损＋保持依赖双全；BCNF 分解保持无损，但不一定能保持函数依赖**。

### 考点 6：事务 ACID 与实现技术对应

**考点**：四性质含义、由什么机制保证。
**速记**：
- **A 原子性**：全做或全不做（恢复机制 undo）；**C 一致性**：事务前后约束不变（应用＋完整性检查的合谋结果）；**I 隔离性**：并发事务互不干扰（**并发控制/封锁**）；**D 持久性**：提交永久生效（**日志与恢复机制 redo**）；
- 考题眼："提交后不因掉电丢失"→持久性→日志保证。

### 考点 7：并发控制三问题与封锁协议

**考点**：丢失修改、脏读、不可重复读；X/S 锁与三级封锁协议。
**速记**：
- 三问题：**丢失修改**（两写相互覆盖）、**脏读**（读了未提交后被回滚的数据）、**不可重复读**（同事务两次读结果不同）；
- **X 锁**（写锁）排他：与任何锁不相容；**S 锁**（读锁）共享：S 与 S 相容；
- 三级封锁协议：一级（写前加 X 锁持到事务结束）→**防丢失修改**；二级（再加读前 S 锁、读完释放）→**防脏读**；三级（S 锁也持到事务结束）→**防不可重复读**——"锁得越久，防得越全，并发越低"。

### 考点 8：两段锁、死锁与活锁、时间戳

**考点**：2PL 内容与性质、死锁/活锁处理、时间戳协议特点。
**速记**：
- **2PL**：先加锁后释放，**加锁与释放两个阶段不交叉**；性质（必考）：遵守 2PL 的并发事务**一定冲突可串行化**，但**不能防止死锁**；
- 死锁：多事务循环等待；对策＝预防（一次加锁法/顺序加锁法）或检测解除（等待图）；
- **活锁**：某个事务总被优先策略"跳过"、长期得不到执行——解法是排队公平（先来先服务）；
- **时间戳排序**：老事务先行，保证冲突可串行化**且天然无死锁**（不等锁，冲突就回滚重试）。

### 考点 9：可串行化判定（案例计算题常客）

**考点**：冲突可串行化与优先图。
**速记**：
- 冲突操作对：同数据上的 read-write、write-write（不同事务间）；
- **优先图（前驱图）**：按冲突先后连边 Tᵢ→Tⱼ；**无环 ⇔ 冲突可串行化**；有环即不可串行化（等价串行序＝拓扑序）；
- 判定三步：标冲突对→画边→查环。

### 考点 10：恢复技术（WAL、redo/undo、检查点、三类故障）

**考点**：先写日志原则、已提交/未提交事务的处理、检查点、故障分类。
**速记**：
- **WAL**：日志必须**先于**数据修改写入稳定存储——恢复的全部依据；
- 恢复规则：**已提交事务 REDO（正向重做）、未提交事务 UNDO（反向用旧值撤销）**；
- **检查点**：定期刷盘并记录，恢复只从最近检查点扫起，大幅缩短扫描与恢复时间；
- 三类故障：事务故障（逻辑错，undo 单个）、系统故障（掉电，重启后按日志 redo/undo）、**介质故障（磁盘坏，必须后备副本＋日志重做，破坏性最大）**。

### 考点 11：完整性约束与触发器

**速记**：
- 三类完整性：**实体完整性**（主键非空唯一）、**参照完整性**（外键存在性）、**用户自定义完整性**（check 等业务规则）；
- 外键删除三策略：**受限删除**（拒绝）、**级联删除**、**置空删除**；
- **触发器**：由 INSERT/UPDATE/DELETE 事件自动激活，实施复杂业务规则与审计。

### 考点 12：数据库安全性

**速记**：安全层次＝用户标识鉴别→存取控制（**GRANT/REVOKE**）→视图（隐藏敏感行列）→审计→数据加密；"只暴露允许列"用**视图＋授权**。

### 考点 13：分布式数据库（2PC、分片、透明性）

**速记**：
- 分片：**水平**（按行/条件）、**垂直**（按列/投影）、混合；
- 透明性层次（由高到低）：**分片透明→位置透明→局部映射透明**（越低层透明越需要用户知道细节）；
- **2PC 两阶段**：①表决（准备）阶段——协调者问"能提交吗"，参与者写好准备日志（锁不释放）回应；②执行阶段——全 yes 则发 COMMIT，任一 no 则发 ROLLBACK；
- 2PC 缺点（高频）：**协调者单点、参与者持锁阻塞（等待决定期间资源被锁死）**；改进方向：超时策略、协调者选举、3PC、以及"尽量用最终一致替代强一致"。

### 考点 14：NoSQL 与 CAP/BASE

**速记**：
- NoSQL 四类：**键值**（Redis 类，简单快）、**列族**（海量写）、**文档**（JSON 灵活模式）、**图**（关系网络）；
- **CAP**：一致性、可用性、分区容忍**三选二**；网络分区不可避免必选 P，故实际在 C 与 A 间权衡——转账核心选 CP，点赞评论选 AP；
- **BASE**：基本可用＋软状态＋**最终一致**，是 AP 的工程化表达，与 ACID 相对。

### 考点 15：数据仓库/数据湖与选型

**速记**：
- **数据仓库**：面向主题、集成、稳定（不更新）、含历史，服务分析决策（OLAP）；**数据湖**：存原始多格式数据，先存后定模式；
- 选型逻辑（案例/论文通用）：强事务账务→关系型 OLTP；海量日志灵活模式→文档/列族 NoSQL；复杂关系网络→图数据库；分析报表→列存/仓库。
