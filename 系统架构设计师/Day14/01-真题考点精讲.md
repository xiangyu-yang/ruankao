## 二、核心考点精讲

### 考点 1：MVC 与 Web 分层（概念送分区）

**考点**：MVC 三件套职责、分层架构、前后端分离。
**考法**：职责归属判断、优点辨析。
**速记**：
- **Model**＝业务数据＋业务逻辑（独立于展示）；**View**＝数据展示与用户交互；**Controller**＝接收请求→调模型→选视图（协调者，不含业务规则）；
- MVC 收益＝**关注点分离**：逻辑、展示、控制三者可独立修改与测试；
- **前后端分离**：前端管展示交互、后端以 API 提供数据业务，接口契约协作、独立开发部署；
- 典型 Web 三层：**表现层—业务逻辑层—数据访问层**：业务层承接表现层调用、使用数据访问层，是规则与流程的家。

### 考点 2：ORM（对象关系映射）

**速记**：
- ORM＝把程序对象与关系表/行建立映射，以操作对象的方式完成持久化；
- 优点：**屏蔽 SQL 细节提效率、屏蔽方言差异提升可移植性、参数化防注入**；
- 权衡（高频反选题）：**复杂查询的 SQL 可控性下降**——极端场景仍需手写 SQL 优化（如批量、报表），"ORM 不是性能问题的免死金牌"。

### 考点 3：中间件与消息队列（治理必考）

**速记**：
- 中间件＝**位于操作系统与应用之间**，提供通信、数据管理、事务等公共服务，屏蔽底层异构；
- 消息队列两大收益：**异步解耦**（生产者消费者时空解耦）与**削峰填谷**（洪峰排队、按可持续速率消费）；
- 两种模型：**点对点**（一条消息一个消费者）vs **发布-订阅**（向主题发布、多订阅者各得一份）；
- **投递语义**：至少一次＝不丢但可能重复→**消费端必须幂等**；
- **死信队列**：收容多次消费失败/过期消息，防"毒消息"阻塞队列；
- **积压处置**：扩容消费者＋定位慢因＋必要时按优先级丢弃转移；**顺序性**＝按业务键分区，同键消息同分区同消费者顺序处理。

### 考点 4：负载均衡（算法配对题）

**速记表**：

| 算法 | 特点 | 适用 |
|------|------|------|
| 轮询 | 顺序轮流、实现简单 | 实例能力相近 |
| 加权轮询 | 按权重分发 | 实例能力不均 |
| 最少连接 | 分给当前连接最少者 | 请求时长差异大 |
| 源地址哈希 | 同 IP 固定实例 | 简单会话保持 |

- **四层 vs 七层**：四层基于 IP/端口转发（吞吐高、时延低）；七层解析应用协议，可按 URL/Cookie 做内容路由（功能强、开销大）——"四层管流、七层懂内容"；
- **健康检查**：定期探测、自动摘除故障实例、恢复再纳入；
- 会话保持推荐：**会话集中存储＋实例无状态化**（优于粘性会话）。

### 考点 5：分布式事务（选型论证题）

**速记**：
- 根源：一个业务操作跨多个服务与数据库，**本地事务罩不住**；
- 方案谱系：**2PC/TCC**＝强一致（代价：阻塞/业务侵入）；**Saga/本地消息表/事务消息**＝最终一致（代价：中间状态可见窗口）；
- **TCC**＝业务层两阶段：Try 预留资源、Confirm 确认、Cancel 释放——用业务补偿弱化对数据库锁的依赖；
- **本地消息表**要点：业务与"待发送消息"**同一本地事务**写入＋中继异步投递重试＋对账兜底；
- **事务消息**：先发半消息→执行本地事务→提交/回滚消息＋回查兜底；
- 选型依据（答题模板）：**一致性容忍度＋流程时长＋并发量**：核心资金强一致选 2PC/TCC，长流程可容忍最终一致选 Saga/消息表。

### 考点 6：Web 缓存架构（三问必背）

**速记**：
- **CDN**：静态资源入边缘节点就近响应（降时延、卸源站）；**动静分离**：静态走 CDN/Nginx、动态走应用，各得其所；**反向代理**：服务端前置代理——静态分发、负载均衡、SSL 卸载、安全防护；
- **缓存穿透**：查**不存在**的数据（恶意键）→缓存库都未命中→**空值缓存/布隆过滤器**；
- **缓存雪崩**：大量 key **同时过期**/缓存整体宕机→**过期时间随机打散＋多级缓存＋高可用集群**；
- **缓存击穿**：**单个热点 key** 失效瞬间请求全砸数据库→**互斥重建（一请求回源）/逻辑过期**；
- 一致性策略：**更新数据库后删除缓存**（不更新缓存）＋过期兜底＋延迟双删——"删而非改"是主流实践。
