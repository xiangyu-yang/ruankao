## 二、逐题解析（每题一答一析）

**1. A**【MIPS·D01】MIPS＝主频÷(CPI×10⁶)＝1.8×10⁹÷(3×10⁶)＝600。

**2. B**【执行时间·D01】执行时间＝指令数×CPI÷主频＝(6×10⁹×2)÷(3×10⁹)＝4 秒。

**3. C**【RAID5·D01】可用容量＝(n−1)×单盘＝4×2＝8TB。

**4. D**【并联冗余·D01】并联＝1−(1−0.95)²＝1−0.0025＝0.9975。

**5. B**【海明码·D01】2ᵏ≥n+k+1：k=5 时 32≥24+5+1=30 成立，k=4 时 16＜29 不成立——至少 5 位。

**6. A**【进程状态·D02】运行→阻塞＝任务主动请求资源/等待 I/O；时间片用完才是运行→就绪。

**7. C**【信号量·D02】同步（资源）信号量初值＝可用资源数＝空缓冲区数＝3；互斥信号量才是 1。

**8. D**【银行家算法·D02】安全序列＝使每个进程都能依次获得所需资源并完成执行的进程序列——存在即安全状态。

**9. A**【Belady异常·D02】FIFO 是非栈算法，页框增多缺页反而可能增多；LRU/OPT 是栈算法无此现象。

**10. B**【逻辑独立性·D02】外模式/模式映像保证逻辑独立性；模式/内模式映像保证物理独立性。

**11. C**【E-R转换·D02】m:n 联系必须独立成表，主键为两端实体主键的组合。

**12. D**【范式判定·D05】候选码为（学号,课程号）；课程号→学分构成非主属性对码的部分函数依赖——不满足 2NF，最高为 1NF。

**13. A**【3NF·D05】3NF＝2NF＋消除非主属性对候选码的传递函数依赖。

**14. B**【隔离性·D02】隔离性＝并发事务互不干扰、中间状态对外不可见。

**15. C**【2PL·D05】遵守 2PL 的调度一定冲突可串行化，但不能防止死锁——死锁需另行检测或预防。

**16. D**【CAP·D05】网络分区在分布式环境中不可避免，P 必选，实际权衡发生在 C 与 A 之间。

**17. B**【子网·D03】/29 主机位 3 位，可用主机＝2³−2＝6。

**18. A**【香农·D03】C＝W·log₂(1+S/N)＝4000×log₂101≈4000×6.66≈26.6kbps≈27kbps；20dB 先换算为 S/N＝100。

**19. C**【TIME_WAIT·D03】等待 2MSL：确保最后 ACK 送达对方＋让旧报文自然消亡，防止污染新连接。

**20. D**【OSPF·D03】OSPF 基于链路状态、Dijkstra 最短路径、支持区域划分、收敛快；RIP 是距离向量、最大 15 跳。

**21. A**【DNS·D03】DNS 主要使用 UDP 53（TCP 用于区域传送）；67/68 是 DHCP。

**22. B**【对称加密·D03】对称加密同钥加解密、速度快、适合大数据量，短板是密钥分发——因此工程上与非对称混合使用。

**23. C**【数字签名·D03】私钥签名＋公钥验证实现完整性、认证与不可抵赖，但不提供机密性——需保密须再叠加加密。

**24. D**【Kerberos·D03】基于对称加密＋可信第三方 KDC，以票据访问服务，口令不在线路上传输。

**25. A**【勒索防护·D03】勒索病毒加密文件，最后的防线是离线备份（3-2-1 策略）——有干净副本才有恢复可能。

**26. B**【哈佛结构·D04】DSP 采用哈佛结构：程序与数据分开存储、独立通路，可并行取指取数。

**27. C**【RM判定·D04】U=0.80＞充分条件上界 0.780——充分条件失效，既不能断言可调度也不能断言不可调度，需构造时间表精确验证或改用 EDF（U≤1 可调度）。

**28. D**【DMA·D04】高速大批量设备选 DMA：CPU 干预从"每数据一次"降为"每块一次"。

**29. A**【看门狗·D04】规定时间内未喂狗即判定跑飞/死锁并自动复位；"定期喂狗"是防复位的正常行为。

**30. C**【BSP·D04】板级支持包位于硬件与 OS 之间：上电初始化、硬件抽象、设备驱动。

**31. B**【瀑布模型·D06】需求明确稳定、技术成熟→瀑布；需求模糊选原型，高风险大型项目选螺旋。

**32. D**【敏捷宣言·D06】四对价值观：个体交互＞过程工具、可工作软件＞详尽文档、客户合作＞合同谈判、响应变化＞遵循计划。

**33. A**【XP·D06】结对编程、TDD、持续集成、小型发布、重构都是 XP 实践；CMMI 是过程改进模型，不属于 XP。

**34. B**【RUP·D06】四阶段：初始（愿景）→精化（架构基线）→构建（编码测试）→移交（部署）。

**35. C**【需求获取·D06】"做出来才知道要什么"＝需求模糊→原型法；多方冲突选 JAD，大样本选问卷。

**36. D**【需求分类·D06】"支持 5000 并发"是"做得怎么样"的度量——非功能需求（性能）；功能需求回答"做什么"。

**37. A**【需求跟踪·D06】双向跟踪矩阵：正向回答"需求实现了吗"，反向回答"这个功能是谁要的"——防镀金与漏实现。

**38. B**【开闭原则·D07】对扩展开放、对修改关闭：新增行为靠新增类，不改既有代码。

**39. C**【工厂方法·D07】"由子类决定实例化哪个类"＝工厂方法；按参数返回实例是简单工厂；创建对象族是抽象工厂。

**40. D**【适配器·D07】接口转换使不兼容的类协同＝适配器；保留接口动态加职责是装饰器、统一入口是外观、控制访问是代理。

**41. A**【观察者·D07】一对多依赖＋状态变化自动通知＝观察者（发布-订阅），MVC 中 Model→View 即此。

**42. B**【extend·D07】"条件成立才执行、可选"＝扩展 extend（箭头：扩展用例→基用例）；"必然执行"才是 include。

**43. C**【组合vs聚合·D07】判据＝生命周期是否绑定：按钮随窗口生灭＝组合；车队-汽车可独立存在＝聚合。

**44. A**【逻辑视图·D08】逻辑视图＝功能分解（类、机制），面向最终用户与领域专家；开发视图面向程序员、进程视图面向集成人员、物理视图面向运维。

**45. D**【ADL三要素·D08】构件、连接件、架构配置；实体-属性-联系是 E-R 模型。

**46. B**【架构复审·D08】复审安排在文档化之后、实现之前——在缺陷放大前发现风险、错误与遗漏。

**47. C**【响应度量·D09】六要素中响应度量以可测指标刻画响应好坏（时延毫秒、恢复秒数、变更人天）——"好需求必须可验证"的落点。

**48. D**【性能战术·D09】增加缓存/负载均衡/数据复制属资源管理；减少计算开销属资源需求；调度策略属资源仲裁。

**49. A**【可用性战术·D09】心跳/ping-echo 属错误检测；冗余/回退/备件属错误恢复；事务/预测属错误预防。

**50. B**【可修改性度量·D09】可修改性响应度量＝完成规定变更的时间、成本与影响范围；A 是吞吐、C 是可用性。

**51. C**【权衡点·D09】同时影响多个质量属性且相互制约＝权衡点（如加密提升安全但降低性能）。

**52. D**【管道-过滤器·D10】编译器各阶段串接、前级输出作后级输入＝管道-过滤器的教科书案例。

**53. A**【分层缺点·D10】逐层传递的性能开销＋层次边界划分困难；关注点分离与层可替换是分层的优点。

**54. B**【隐式调用·D10】发布者只发布事件、不感知订阅者——调用关系"隐含"在事件订阅中，故名隐式调用。

**55. C**【黑板·D10】无确定性求解算法、多知识源渐进协作（语音识别、图像理解）＝黑板风格画像。

**56. D**【B/S·D10】B/S 瘦客户端零安装跨平台、升级只改服务端；交互与服务器压力恰是其短板。

**57. A**【微服务拆分·D11】拆分依据＝业务能力与领域边界（限界上下文），绝不按代码行数或人头均分。

**58. C**【Saga·D11】Saga＝多个本地事务＋补偿动作，任一步失败逆向补偿——最终一致的主流方案。

**59. B**【K8s·D11】Kubernetes 核心能力：自动装箱调度、服务发现、弹性伸缩与自愈（故障实例自动重建）。

**60. D**【Serverless·D11】无服务器＝开发者不管基础设施，事件触发函数、按用量计费、天然弹性——服务器仍存在，只是对开发者透明。

**61. A**【ABSD·D12】三方驱动：功能需求（用例）＋质量属性需求（质量场景）＋商业需求（约束）。

**62. B**【参考架构·D12】参考架构＝特定领域可复用的架构模板，DSSA 领域工程的产出与新系统设计的起点。

**63. C**【ATAM步骤·D13】九步：1 介绍→2 商业动机→3 架构描述→4 识别架构方法→**5 生成效用树**→6 分析架构→7 头脑风暴→8 再次分析→9 呈现结果。

**64. D**【权衡点判定·D13】影响多个质量属性且相互制约＝权衡点；只影响一个属性是敏感点。

**65. A**【场景交互·D13】SAAM 场景交互＝两个间接场景作用于同一构件——可修改性冲突与耦合的信号。

**66. B**【回收期·D13】投资回收期＝成本÷年化收益＝100÷25＝4 年。

**67. C**【ORM·D14】ORM 屏蔽 SQL 细节与方言差异、参数化防注入；但复杂查询可控性下降，极端场景仍需手写 SQL 优化。

**68. D**【消息队列·D14】两大收益：异步解耦（时空解耦）与削峰填谷（洪峰排队、按可持续速率消费）。

**69. A**【负载均衡·D14】源地址哈希使同一 IP 固定落到同一实例——简单会话保持；能力不均用加权轮询，请求时长差异大用最少连接。

**70. C**【TCC·D14】TCC＝Try（资源预留）＋Confirm（确认提交）＋Cancel（取消补偿），业务层面的最终一致方案。

**71. B**【英语】质量属性场景六要素含刺激、环境与响应度量（response measure），使需求可测量。

**72. D**【英语】分层架构中每层向其上层提供服务（services），并调用下层服务。

**73. A**【英语】微服务围绕业务能力组织、通过轻量协议（protocols）通信、独立部署。

**74. B**【英语】消息队列支持异步通信，并帮助吸收（absorb）高并发系统中的流量洪峰。

**75. C**【英语】权衡点是以相互冲突（conflicting）的方式影响多个质量属性的决策。
