## 二、逐题解析

**1. A**【论文项目概述】四要素＝规模投资＋工期＋原有痛点＋本人角色职责；公司历史、技术栈清单、领导讲话均为填充物，写多了挤占正文空间。

**2. B**【分层风格机制】每层仅向相邻层提供服务、单向依赖、关注点分离；A 是管道过滤器、C 是事件驱动、D 是黑板的机制。

**3. C**【微服务论文视角】架构师视角是"拆分依据（限界上下文）＋治理成效"，页面配色、建表语句属实现细节，写论文要向上抽象一层。

**4. D**【管道-过滤器术语】理论段术语组合：数据流、过滤器独立性、顺序/并行组合；准确术语是"理论正确性"的直接得分点。

**5. A**【C2 风格】C2 经连接件向上发请求、向下收通知，底层不感知上层细节——"消息单向流动＋层次不对称"是它的身份标识。

**6. B**【仓库风格】多客户端围绕中央共享数据做查询/更新/统计是仓库（数据库型）的典型场景；注意与"黑板型由数据状态触发求解"相区分。

**7. C**【论文取舍写法】写消息延迟与最终一致性的争议，正确姿势是"承认代价＋给出监控补偿设计"——回避缺点或宣称完美都削弱可信度。

**8. D**【黑板机制】黑板＝中央数据结构的当前状态触发知识源机会式求解；语音识别、专家系统是论文里的标配案例。

**9. D**【闭环控制选型】温度/压力等过程参数自动调节是闭环控制（传感-计算-执行-反馈）的教科书场景，搜索、支付、推荐均无反馈回路特征。

**10. C**【组合风格采分】组合风格三采分点：各风格各承担什么质量目标、为何单一风格不够、组合新增风险与对策——列举数量本身不加分。

**11. C**【微服务 vs SOA】粒度、独立部署、治理方式三差异是论文素材级要点；"都用 ESB/SOAP/都不支持分布式事务"表述皆错。

**12. D**【分层的代价】为可修改性增抽象层，代价是调用链变长的性能开销——"可修改性↑性能↓"是分层论文里现成的权衡点素材。

**13. A**【理论段定位】500 字理论段是"理论正确性"的直接得分区：定义、构成、机制、优缺点须教科书级准确。

**14. B**【不足与体会】主动写不足体现自我批判与方法论沉淀，是高分卷的标配；不写反而显得论证浅、可信度低。

**15. D**【人称与角色】"本人担任系统架构师"必须出现并贯穿个人决策视角；通篇"我们团队"是阅卷人识别套作的信号之一。

**16. D**【数字运用】规模类、对比类（改造前后）、成效类数字至少各两组；全用"大量、显著"形容词是空洞卷的典型特征。

**17. C**【选型对比写法】高分公式："对比 A 与 B，因场景 C 特性选 A，代价 D、对策 E"——只写选中方案优点则论证力不足。

**18. B**【真实感素材】写一次返工/争议再调整比全程顺分更可信，也提供了"难点与取舍"的叙事载体，是论文增强论证深度的常用笔法。

**19. A**【摘要四句定式】背景一句＋角色一句＋方案两句＋成效一句；摘要 300 字是阅卷人形成第一印象的唯一入口。

**20. C**【角色缺失后果】摘要不写角色→疑似套用范文、实践可信度打折，直接影响得分档次——这也是"双保险"检查的第一项。

**21. A**【正文四段分配】概述 400／理论 500／实践 900-1000／效果与体会 300——记忆锚点"4-5-9-3"。

**22. A**【论点内部结构】理论依据→方案与选型对比→难点取舍→量化效果，四步缺一不可；实践段是论文的腰，腰硬全文硬。

**23. C**【理论实践配比】约 3:7——通篇理论是教材默写、通篇实践是项目总结，两者都够不着及格线的"架构师论文"定义。

**24. D**【机考环境】机考屏幕阅读更易疲劳：段落间合理空行、避免超长段落；特殊符号装饰不加分。

**25. C**【换皮重写】保留骨架与论证逻辑、替换行业背景完整重写——这是 25-27 论文日"同主题换背景"训练的方法论入口，抄原文则毫无意义。

**26. B**【范文精读四步】拆骨架（验证模板）→拆数字（建数字库）→拆术语（建得分词表）→换皮重写（验证迁移能力）。

**27. A**【评分四维】结构完整性、理论正确性、实践可信度、文字表达——按此四维自检论文是交付前最后一道闸。

**28. D**【匿名化】真实公司名/人名一律匿名化为"某集团、某省"——既保护信息又显专业分寸，写实名是低级失误。

**29. C**【理论实践失衡】两者均可能不及格：前者是教材默写、后者是项目总结——论文要的是"理论指导下的实践"。

**30. C**【首尾呼应】收尾呼应摘要核心结论形成闭环；收尾否定摘要说明成文逻辑混乱。

**31. B**【重要数据】"重要数据"指泄露后可能危害国家安全、公共利益的数据，目录由行业主管部门识别发布；与"商业秘密"分属不同维度。

**32. B**【最小必要】处理目的限定＋收集范围限于实现目的所必需——目的与手段成比例，是个人信息合规的第一原则，也是合规论文的理论支点。

**33. A**【留痕三要素】操作时间、操作主体、操作内容（对何对象做了什么）——三要素缺一则审计链断；IP/浏览器等是辅助字段。

**34. B**【审计追踪链路】从用户发起、各层处理到数据变更全链路可关联、可回放、可举证；只在数据库记访问日志是"断链审计"，举证时对不上号。

**35. A**【算法合规】"用户可选择退出"针对推荐画像与个性化展示的自动化决策——个人信息保护要求对自动化决策给予拒绝/解释渠道。

**36. D**【出境评估】向境外提供重要数据或达到规定规模的个人信息须申报数据出境安全评估；境内机房同步、浏览器访问均不构成出境。

**37. B**【元数据引擎】低代码核心：以元数据描述表单/流程/权限，运行时解释执行，改配置不改代码——这是低代码论文理论段的定义句。

**38. B**【模型驱动开发】MDD 以模型为核心制品，由模型生成或解释为可运行系统；模型不是画完即弃的图，而是可执行的一等公民。

**39. D**【逃生舱】可视化覆盖不了复杂逻辑时，以脚本/插件/标准 API 编写专业代码并封装复用——"逃生舱"边界设计是低代码论文的关键论点。

**40. A**【平台治理】版本管理解决应用全生命周期问题：多环境隔离、变更留痕、可回滚——应用数量增长后"不失控"靠的是治理而非自觉。

**41. B**【响应时间与吞吐】响应时间衡量单请求快慢、吞吐量衡量单位时间完成数；提升吞吐（并发）常以牺牲单请求延迟为代价，论文性能段的标准权衡素材。（Day01 滚动复习）

**42. A**【进程与线程】进程是资源分配基本单位、线程是 CPU 调度基本单位，同进程内线程共享地址空间——一句话定义选择题年年考。（Day02 滚动复习）

**43. D**【默认端口】HTTPS 默认 443；21 是 FTP、80 是 HTTP、8080 是常用自定义端口——端口号是稳定考点可放心记。（Day03 滚动复习）

**44. D**【MTTR】平均修复时间（故障→恢复）；MTBF 是平均故障间隔。可用度＝MTBF/(MTBF＋MTTR) 中的分母正是"MTBF＋MTTR"。（Day04 滚动复习）

**45. A**【瀑布模型】阶段线性顺序、文档驱动，适合需求稳定项目；需求易变场景应选迭代/敏捷——"模型与需求稳定性匹配"是选型题眼。（Day05 滚动复习）

**46. C**【JAD】联合应用开发：用户与开发方通过联合工作坊协同确定需求，效率高于逐一访谈；问卷/观察是其他获取手段。（Day06 滚动复习）

**47. B**【观察者模式】观察者属行为型模式（一对多依赖、状态变更自动通知）；结构型如适配器，创建型如工厂。（Day07 滚动复习）

**48. D**【逻辑视图】4+1 中逻辑视图面向最终用户、描述系统功能（对象模型）；开发视图面向程序员、进程视图面向系统集成、物理视图面向运维。（Day08 滚动复习）

**49. C**【可测试性战术】记录-回放捕获输入与状态，用于复现故障、隔离被测件；它属于可测试性战术的"控制与观察系统"类。（Day09 滚动复习）

**50. B**【服务网格】Sidecar 以独立代理接管服务间通信治理（发现、路由、熔断），业务代码零侵入——"治理下沉"是网格相对 SDK 方式的核心差异。（Day11 滚动复习）

**51. A**【ABSD 过程】ABSD 设计活动：架构需求→生成候选架构→架构描述→架构复审→实现；架构复审通过后才进入实现。（Day12 滚动复习）

**52. A**【效用树标注】(H, L)＝高重要度、低实现难度——此类"重要且相对易达成"的场景是评估中优先深入分析的甜点区。（Day13 滚动复习）

**53. D**【MVC】Model 封装业务数据与逻辑；View 渲染界面、Controller 接收请求并调度——三者职责分离是 Web 架构论述的起手式。（Day14 滚动复习）

**54. B**【水平分片】水平分片按行（用户 ID 取模）拆散同表；按业务功能拆库是垂直拆分。读写分离缓解读、分片缓解写——两句话配套记忆。（Day16 滚动复习）

**55. B**【RAID 5】RAID 5 以分布式奇偶校验允许一块盘故障，兼顾容量利用率与安全；RAID 1 镜像最安全但利用率仅 50%。（Day17 滚动复习）

**56. B**【RM 调度】速率单调：周期越短优先级越高的静态优先级实时调度；EDF 才是动态优先级。RM 可调度性判定利用率边界是经典计算考点。（Day18 滚动复习）

**57. C**【数据湖】数据湖以原始格式集中存储多源异构数据（结构化/半结构化/非结构化），供多引擎按需分析；"先汇聚后 schema"是与仓库的本质差异。（Day19 滚动复习）

**58. B**【冷启动】FaaS 实例长时间无调用被回收，下次调用重新初始化带来延迟——低频函数受影响最大，论文谈 Serverless 必谈此权衡。（Day20 滚动复习）

**59. A**【SAAM 场景交互】不同场景修改涉及同一构件→该构件变更频繁、是敏感构件——SAAM 以此发现架构的变更热点。（Day23 滚动复习）

**60. A**【ping/echo】ping/echo 属可用性战术的错误检测类（与心跳、监控同组）；错误预防、恢复是另外两类。（Day22 滚动复习）

**61. B**【风险主题】风险主题是相关风险点归并后的系统性隐患类别（如"单点设计贯穿多个场景"），价值在于揭示共性架构问题。（Day21/23 滚动复习）

**62. C**【双机热备】1−(1−0.9)²＝1−0.01＝0.99；双机冗余把可用度从 0.9 提升到 0.99——试卷里最常出现的可用度计算。（Day01 滚动复习）

**63. D**【隔离级别】串行化最高（完全隔离）；读未提交最低（脏读）。四级别从脏读→不可重复读→幻读逐级解决。（Day02 滚动复习）

**64. C**【网络层】路由器工作在网络层（路由选择）；交换机在数据链路层、集线器在物理层、网关在高层——设备与层次配对是送分题。（Day03 滚动复习）

**65. A**【交叉开发】嵌入式在宿主机（x86 工作站）上开发编译、目标机（嵌入式板）上运行调试，成对环境即交叉开发。（Day04 滚动复习）

**66. A**【燃尽图】燃尽图展示迭代剩余工作量随时间下降；每日站会后更新，用于暴露进度风险。（Day05 滚动复习）

**67. C**【变更控制】变更五步：申请→影响分析（跟踪矩阵定位波及面）→CCB 审批→实施验证→更新基线；无审批直接改是典型反模式。（Day06 滚动复习）

**68. D**【适配器模式】适配器把一个接口转换成客户期望的另一接口，使不兼容类协同——遗留系统对接新接口是它的论文级用例。（Day07 滚动复习）

**69. D**【ADL 连接件】连接件描述构件间交互（调用、消息、数据流等）；"网线/外键"是干扰项，ADL 是逻辑概念。（Day08 滚动复习）

**70. C**【响应度量】"3 秒"是对响应的量化度量；刺激是"提交订单请求"、制品是"订单受理模块"——六要素拆解是案例必做题的基本功。（Day09 滚动复习）

**71. C**【专业英语】audit trail＝审计追踪链路：可回放"谁、何时、对何数据、做了什么"，为合规调查提供证据——对应中文考点 34 题。

**72. B**【专业英语】metadata engine＝元数据引擎：运行时解释表单/流程/权限元数据，改配置不改代码——低代码平台的定义级术语。

**73. A**【专业英语】model-driven development＝模型驱动开发：模型是核心制品，运行系统由模型生成或解释而来。

**74. D**【专业英语】data security-level classification＝数据安全等级分类（公开/内部/敏感/机密），各级配不同防护强度——对应数据分类分级考点。

**75. C**【专业英语】escape hatch＝逃生舱：可视化编排覆盖不了复杂逻辑时，允许编写专业代码并封装为可复用插件——低代码平台治理的关键词。
