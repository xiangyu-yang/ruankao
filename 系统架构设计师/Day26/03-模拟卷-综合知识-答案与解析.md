## 逐题解析

**1. B**【渗透测试定义】关键词"授权＋模拟攻击"——未授权即违法，这是渗透测试与黑客攻击的法律边界。

**2. A**【STRIDE】六类威胁首字母：Spoofing 假冒、Tampering 篡改、Repudiation 抵赖、Information disclosure 信息泄露、Denial of service 拒绝服务、Elevation of privilege 权限提升——S 是假冒。

**3. A**【STRIDE】T＝Tampering 篡改——六大威胁至少背三对（S/T/I），论文里能点名即加分。

**4. C**【威胁建模时机】安全左移的核心动作：在设计阶段画数据流图（DFD）、逐元素套 STRIDE——上线后建模只能"亡羊补牢"。

**5. A**【SAST vs DAST】SAST 白盒扫代码（不需运行、覆盖全代码、误报偏高）；DAST 黑盒打运行态（贴近真实攻击、误报低、覆盖率受用例限制）——一静一动互补成对。

**6. A**【SCA】软件成分分析＝对第三方组件/依赖做已知漏洞（CVE）扫描——开源依赖是现代应用最大的隐性攻击面，DevSecOps 流水线必配。

**7. A**【IAST】运行时插桩＋实时检测＝低误报的灰盒方案，适合功能测试阶段同步做安全检测——"测试人员顺手做安全"的落地技术。

**8. C**【安全左移】左移的本质是经济学：设计期修复缺陷的成本约为上线后的 1/10~1/30——论文里这笔账是硬论据。

**9. B**【漏洞 SLA】分级＋时限是漏洞治理的牙齿：高危 72 小时、中危 7 天、低危随版本——只报不修等于没测。

**10. A**【红蓝对抗】红攻蓝防的实战化演练，是渗透测试之上的组织级安全能力检验——论文的高分素材点。

**11. A**【维度建模第一步】四步法顺序：业务过程→粒度→维度→事实——先选业务过程（如"票务交易"），建模才有靶心。

**12. C**【粒度声明】第二步声明粒度："一行代表一笔交易还是一天一家影院的汇总"——粒度决定后续一切，答错方向全错。

**13. B**【星型模型】事实居中、维度直连、冗余换查询速度——BI 场景首选，选它的理由在论文里要写成对比结论。

**14. A**【雪花模型】维度规范化拆分的代价是查询多表 JOIN——存储省但查询慢，与星型取舍是维度建模经典考点。

**15. C**【事务型事实表】记录每笔事件（每张票）＝事务事实表；周期快照（每天余额）、累积快照（流程里程碑）是另两类——三类事实各对一类业务。

**16. B**【SCD Type 2】Type 2＝新增行＋生效区间（拉链表）留全历史——影院改造、门店签约类档案变更必须用 Type 2 才能回溯历史口径。

**17. B**【ODS 层】贴源原样入仓，保持与源系统一致的审计与重放能力——"原样"二字是 ODS 的身份证。

**18. A**【ADS 层】应用集市层：面向报表与应用的最上层，直接服务集市与 BI——四层分工在论文分层治理里各一句话。

**19. C**【总线矩阵】行为业务过程、列为共享维度，保证全企业维度一致性——一致性维度是 Kimball 方法的"总线"，集市才能拼装。

**20. A**【数据集市】集市＝面向主题/部门的分析子集，从企业级数仓派生（依赖集市）或独立建设（独立集市）——与数仓是子集关系不是替代关系。

**21. D**【场景六要素】刺激源/刺激/制品/环境/响应/响应度量——质量属性场景题的答题骨架，六个要素缺一即失分。

**22. B**【敏感点】只影响一个质量属性的决策点（如加密强度影响机密性）——"一个"是敏感点的判别词。

**23. C**【权衡点】影响多个质量属性（加密影响安全＋性能）——跨属性是权衡点与敏感点的分界，考案例必考。

**24. D**【ATAM 目的】输出不是"最优架构"而是"风险可接受的共识"——评估的本质是暴露风险与权衡、统一干系人预期。

**25. D**【效用树】属性→场景→（重要性,难度）H/M/L 优先级排序——ATAM 第 3 步的产出物，把"抽象属性"翻译成"可评估场景"。

**26. B**【ATAM 九步】Step1-3（呈现方法/商业动机/效用树）→**Step4 架构师呈现架构**→Step5-6 调查分析→Step7-8 头脑风暴场景再分析→Step9 结果呈现——九步主干必背。

**27. C**【4+1 视图】逻辑/开发/进程/物理四视图＋场景（用例）串联——"+"1 是场景。

**28. B**【管道-过滤器】数据流逐级转换的经典风格（编译器、ETL）——不适合交互密集场景，风格选型题的对称考点。

**29. C**【分层风格】关注点分离、逐层依赖——优点（可维护/可复用）与缺点（跨层开销）都要会写。

**30. B**【微服务拆分】按业务能力与限界上下文，不按代码行数不按人头——拆分依据是论文微服务主题的第一论点。

**31. C**【服务发现】注册中心（如 Nacos）实现动态寻址＋负载均衡——微服务"三大件"（注册/配置/网关）之一。

**32. B**【消息队列削峰】异步化把洪峰转为平稳消费——秒杀场景的标准答案，注意配"最终一致"补偿设计。

**33. A**【CAP】网络分区（P）必选，C 与 A 二选一——CP（银行转账）还是 AP（点赞计数）按业务选，考试爱给场景判断。

**34. A**【BASE】基本可用、软状态、最终一致——CAP 工程化的妥协方案，与"强一致"对照记忆。

**35. C**【读写分离】主写从读＋主从复制——写少读多场景的扩容第一招，注意复制延迟的处理（读己之写）。

**36. D**【缓存穿透】不存在的 key 绕过缓存直击数据库——对策：布隆过滤器/空值缓存/参数校验，三招必背。

**37. D**【缓存雪崩】大量 key 同时过期——对策：过期时间加随机抖动、多级缓存、熔断限流，与穿透（不存在 key）区分。

**38. C**【哈希取模】shard = hash(key) % N——扩容会大规模迁移是缺点，一致性哈希解决，对比必考。

**39. C**【MVC】Model 业务与数据、View 展示、Controller 接收转发——三职责别混，MVC 与三层架构的对应关系是经典陷阱。

**40. A**【ORM】对象关系映射屏蔽 SQL——注意 N+1 查询陷阱，架构师论文可作技术细节加分。

**41. D**【MTBF】平均无故障时间＝正常运行总时间/故障次数——可靠性的核心指标，与 MTTR（修复）配对。

**42. B**【可用度公式】A＝MTBF/(MTBF＋MTTR)——数字题常给 MTBF=999 小时、MTTR=1 小时求 99.9%。

**43. D**【串联可靠度】串联相乘：0.9×0.9=0.81——并联（冗余）用 1－(1－R)²，两公式对称考。

**44. C**【双机热备】状态同步＋故障切换——提高可用性的本质是"冗余＋快速接管"，与集群负载均衡的场景区分。

**45. D**【看门狗】定时喂狗、超时复位——嵌入式可靠性的看家本领，论文嵌入式主题的标配细节。

**46. B**【RM 调度】周期短优先级高（静态优先级可调度利用率上限定理约 ln2 与 n 有关，不必展开）——与 EDF（动态、截止期最早优先）成对考。

**47. A**【EDF】截止期最早优先——动态调度理论最优，RM 静态简单稳定，按场景取舍。

**48. C**【进程线程】线程＝调度执行单位、进程＝资源分配单位——一字之差两个"单位"，选择题常考搭配。

**49. D**【ACID·I】隔离性（Isolation）——并发事务互不干扰；四个字母对应的中文术语要全。

**50. B**【两阶段锁】扩展（只加不释放）→收缩（只释不加）——遵守 2PL 保证串行化但可能死锁，与超时检测配套。

**51. A**【3NF】消除传递依赖——1NF 原子、2NF 消除非主属性对码的部分依赖、3NF 传递依赖，层层递进。

**52. C**【B+树】叶子有序链表＋树矮胖适配磁盘页——范围查询与磁盘 I/O 是两个关键词。

**53. D**【视图】虚表＝查询定义，不存数据——视图的安全（行/列权限）与简化查询作用可并考。

**54. B**【索引代价】空间＋写入拖累——"索引越多越好"是经典错误直觉，读多写少才适合多索引。

**55. A**【三次握手】SYN → SYN+ACK → ACK——防止历史重复连接初始化，两次不行的原因是"无法确认双向收发能力"。

**56. D**【TLS 握手】非对称只管协商对称密钥（快加密大数据）——混合加密是"非对称之慢换密钥交换之安全"，必背标准答案。

**57. D**【VLAN】逻辑隔离广播域——安全与流量的双收益，与子网（物理/逻辑边界）区别常考。

**58. B**【DNS】域名→IP——递归与迭代查询的差别是加分点。

**59. D**【RAID5】条带化＋分布式校验，坏一块不丢数据——写性能有校验开销，与 RAID10（镜像条带）取舍看写负载。

**60. C**【奈奎斯特】无噪声极限速率 C=2W log2V——有噪声用香农 C=W log2(1+S/N)，两公式与条件对应考。

**61. D**【云原生】容器＋微服务＋DevOps＋持续交付——P8C 女生？记组合即可，云原生不是"上云"。

**62. B**【Serverless】FaaS/BaaS：免管服务器、事件驱动、按量计费——冷启动延迟是代表性缺点，论文可作权衡素材。

**63. A**【Lambda 三层】批处理层（全量准确）＋速度层（实时增量）＋服务层（合并查询）——批流双跑，代价是双系统复杂。

**64. D**【Kappa】一切皆流、一套代码——用可重放日志（如 Kafka 长保留）替代批层，简化 Lambda 但重算成本高。

**65. D**【Kafka 高吞吐】分区并行＋顺序写盘＋零拷贝——三件套背齐，选做新技术题的答案骨架。

**66. D**【GB vs GB/T】GB 强制、GB/T 推荐——数字红线：软件生存周期过程（GB/T 8566）、文档（8567）都是推荐性。

**67. B**【机房规范】数据中心/机房设计规范——含供电、制冷、防雷、消防等工程要求，架构师考综合偶尔涉及。

**68. C**【ISO 27001】信息安全管理体系（ISMS）——与 20000（IT 服务）、9001（质量）三分法记。

**69. D**【国密算法】SM2（非对称椭圆曲线）、SM3（哈希）、SM4（对称分组）——自主可控论文的标配术语。

**70. A**【软件著作权】自开发完成自动产生——与专利"先申请"对照，数字红线再确认。

**71. B**【专业英语】authorized simulated cyberattack——"授权"是渗透测试定义的必选词，选 A（accidental）或 C（real malicious）即张冠李戴。

**72. D**【专业英语】threat modeling in the design phase——威胁建模的英语锚点，对应安全左移主题。

**73. A**【专业英语】star schema＝central fact table surrounded by dimension tables——星型模型的英语定义原文。

**74. C**【专业英语】data mart＝subject-oriented subset——集市的"子集"定位，superset 恰为反向陷阱。

**75. B**【专业英语】utility tree——ATAM 的效用树，质量属性主题的术语锚点。
