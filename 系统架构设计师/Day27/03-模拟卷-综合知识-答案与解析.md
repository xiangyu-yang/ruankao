## 二、逐题解析

**1. A**【执行计划】type＝ALL 即全表扫描，是访问方式阶梯（const→ref→range→index→ALL）的最底层，SQL 优化的第一目标就是消除全表扫描。

**2. B**【索引失效-函数】对索引列做函数运算（YEAR(col)、SUBSTR(col)）会破坏索引有序性导致失效；正确做法是把函数移到常量侧或建函数索引。

**3. C**【最左前缀】联合索引 (a,b,c) 只能命中以 a 开头的查询：WHERE b=5 缺最左列，索引整体不可用——"最左前缀"是联合索引第一铁律。

**4. A**【覆盖索引】查询列全部含在索引中即"免回表"，EXPLAIN 的 Extra 出现 Using index——高频查询做覆盖索引是免读数据的经典优化。

**5. A**【索引选择性】选择性＝列唯一值数/总行数，越接近 1 区分度越高、过滤性越好；低选择性列（如性别）单独建索引收益甚微。

**6. D**【隐式转换失效】字符串列与数字比较触发隐式类型转换，等价于对列套函数，索引失效——字符列条件请加引号保持同型。

**7. C**【LIKE 与索引】前导通配 '%abc' 使 B+ 树有序性无从定位，不走索引；'abc%' 保留前缀有序可用。口诀"前缀能走、前导不走"。

**8. C**【OR 与索引】OR 两侧有一列无索引，优化器通常放弃索引改全表扫描——改写为 UNION 或补齐索引是两条对策。

**9. A**【慢查询闭环】治理是闭环工程：慢日志采集（阈值如 1 秒）→评审归因→优化→回归验证→沉淀知识库，防"优化-反弹-再优化"循环。

**10. B**【写入放大】每个索引都是一棵独立 B+ 树，INSERT/DELETE/UPDATE 需同步维护所有相关索引——索引"越多读越快、写越慢"，须按查询权衡数量。

**11. D**【统计信息过期】rows 估算严重失真源于统计信息过期，优化器据此选错计划（该走索引却全表）；ANALYZE TABLE 更新统计即可纠偏。

**12. B**【建索引判断】高选择性＋高频查询条件列是建索引首选；低选择性列建议联合索引中作非前导列或干脆不建。

**13. C**【前缀索引】长字符串列取前 N 字符建索引，N 取"区分度接近整列"的最小值，兼顾检索效果与空间成本。

**14. C**【联合索引设计】顺序设计看查询模式：让最左列被等值条件命中、兼顾区分度——"查询决定顺序"而非"表定义决定顺序"。

**15. C**【回表】二级索引叶子存主键值，命中后还需到聚簇索引取整行即"回表"；回表次数多时考虑覆盖索引。

**16. A**【主键设计】顺序递增短主键使新行总追加到 B+ 树最右端，避免随机插入引发页分裂；UUID 作主键是 InnoDB 大表的常见反模式。

**17. B**【慢查询日志】慢日志回答"谁慢、多慢、何时"，是优化工作的数据源与优先级依据——没有度量的优化都是猜。

**18. D**【不等条件】<>、NOT IN 通常选择性差、优化器倾向放弃索引（取决于实际区分度）——表述"通常"留有余地，选项其余三项均可有效用索引。

**19. D**【SQL 审核治理】治理平台的核心是"上线前拦截"：自动化规则校验（缺索引、全表扫描风险、危险语法）把问题挡在投产前，比事后救火成本低一个量级。

**20. C**【优化优先级】定位先行（执行计划/慢日志）→SQL 与索引→结构（读写分离/分片）→最后才是硬件扩容——成本从低到高的阶梯是数据库优化方法论。

**21. A**【服务识别】自顶向下：从业务能力分解候选服务；自底向上：从现有系统功能盘点现有资产——两向对齐防"凭空设计"与"照单全收"两个极端。

**22. C**【服务资产库】资产库让服务像图书馆一样可检索：注册（元数据）、分级分类、检索复用统计——服务从"代码"升格为"可管理资产"。

**23. B**【API 生命周期】设计→评审→发布→版本演进→废弃下线，五阶段缺"评审"则质量失守、缺"废弃"则资产库变垃圾场。

**24. B**【接口契约】契约＝请求参数、响应结构、错误码、版本约定的明确文档；契约先行（design-first）是 API 治理与自动化测试的前提。

**25. A**【API 网关职责】统一入口四件事：鉴权认证、流量控制（限流熔断）、路由转发、监控审计——业务逻辑留在服务，横切能力上收网关。

**26. C**【API 版本管理】显式版本标注（URI/header）＋旧版废弃前过渡期与通知，是"不破坏调用方"的兼容性纪律——直接覆盖旧接口是治理事故第一名。

**27. C**【契约测试】契约测试自动验证提供方实现与契约、消费方预期与契约双向一致，让"接口改了没人知道"的事故在 CI 阶段暴露。

**28. B**【配额管理】配额按调用方分配 QPS/日调用量，防止单一第三方刷爆平台总容量——开放平台"先保己再开放"的护栏。

**29. A**【服务分级】核心/重要/一般三级匹配不同 SLO、监控强度与治理投入——资源有限，把最重的护栏装在最重要的服务上。

**30. B**【复用率】复用率＝被多消费方复用的服务占比，衡量服务资产化成效的核心指标——复用率上不去说明"资产库"只是"仓库"。

**31. D**【API 下线治理】规范下线四步：提前通知→标注废弃→观察期监控残余调用→正式下线归档；直接关停是对生态的自杀式操作。

**32. A**【开放平台安全】AppKey/密钥＋请求签名（HMAC 防篡改）＋HTTPS 防窃听＋最小授权范围（scope）——开放不是裸奔。

**33. A**【五步闭环】现象与量化→归因与理论→方案与对比→实施与代价→效果与验证——专项论文论点的标准解剖结构，缺"代价"则论证不完整。

**34. B**【产品说明书陷阱】罗列技术特性而无"为什么这么选"是专项论文第一陷阱；采分点在论证链而非名词密度。

**35. C**【新技术论文要点】适用性论证四问：解决什么、不解决什么、代价是什么、何时不用它——新技术题考的是架构判断力不是追新热情。

**36. D**【演进性叙事】写出定位与归因过程（怎么发现慢、怎么排除假因）比一次性成功的结论更有看点——过程见真功，结论人人有。

**37. A**【拆归因链】范文精读第五步：专项论文的灵魂在"从现象到原因"的推理段——这段最难抄也最值得学。

**38. A**【考前收敛策略】考前 3 天不再开新方向，把 25-27 六篇范文收敛为两套万能模板（风格/评估类、专项/新技术类）各配一个熟练背景。

**39. C**【摘要冲刺】摘要达可默写状态：骨架固定＋术语自动化，考场把背景数字替换即可产出——300 字摘要质量决定第一印象。

**40. D**【限时全真】120 分钟 2500 字左右全文敲写（含摘要）是达标线——写提纲代替全文不算训练，速度与体力必须提前验证。

**41. A**【Amdahl 定律】S＝1/((1−f)＋f/k)＝1/(0.25＋0.75/3)＝1/0.5＝2——加速比受串行部分 25% 封顶，整体翻倍已是上限。（Day01 滚动复习）

**42. B**【共享内存】共享内存是进程间最快的通信方式（直接读写同一内存区，仅需同步原语）；管道/消息队列/套接字均有内核拷贝开销。（Day02 滚动复习）

**43. C**【C 类默认掩码】C 类默认 255.255.255.0（/24）；A 类 255.0.0.0、B 类 255.255.0.0——分类编址默认掩码是子网计算的地基。（Day03 滚动复习）

**44. D**【实时系统特性】RTOS 的灵魂是时间确定性：任务完成时间可预测、有上界——快不快是其次，"确定不确定"才是分水岭。（Day04 滚动复习）

**45. B**【结对编程】两人一机互为实时代码评审：缺陷预防前置＋知识传递扩散，是 XP 最具辨识度的实践。（Day05 滚动复习）

**46. B**【原型分类】抛弃式原型验证需求后丢弃（防止劣质原型演化成系统），演化式原型逐步加固直至成为最终系统——先想清楚要哪种。（Day06 滚动复习）

**47. A**【实现关系】实现连接接口与实现类（虚线空心三角）；泛化连接类与其父类（实线空心三角）——两者箭头线型是类图辨析高频点。（Day07 滚动复习）

**48. D**【动态演化】动态演化指运行期间的架构调整（属性变更、服务替换）且不中断服务，静态演化则是停机重构——区分"动/静"看是否运行中。（Day08 滚动复习）

**49. C**【检测攻击】IDS 入侵检测属安全战术的"检测攻击"类（与审计追踪同组）；"抵抗攻击"含认证授权加密，"从攻击中恢复"含审计回溯。（Day09 滚动复习）

**50. A**【解释器风格应用】规则引擎以解释方式执行外部化的业务规则，是解释器风格在企业系统的典型化身——规则即"被解释的程序"。（Day10 滚动复习）

**51. B**【不可变基础设施】镜像只读分层、变更即新镜像＋重新部署，杜绝"运行环境上手工打补丁"的漂移——回滚＝换回旧镜像。（Day11 滚动复习）

**52. D**【架构复审关注点】ABSD 复审验证架构是否满足质量属性需求（性能/可用性等），功能正确性留给后续测试——评审的是"属性"不是"功能"。（Day12 滚动复习）

**53. D**【ATAM 第 7 步】第 7 步：头脑风暴并确定场景优先级，此时全体涉众参与、场景由多数票定级——第 1-6 步是评估组内的第一遍。（Day13 滚动复习）

**54. B**【L4 vs L7】L4 按 IP/端口转发（不解载荷、快），L7 解析 HTTP 等应用协议可按路径/Cookie/内容路由（智能但更重）——七层均衡是应用交付主战场。（Day14 滚动复习）

**55. C**【缓存穿透】穿透＝查询根本不存在的数据，缓存永远不命中直压数据库（常为恶意构造）——对策：布隆过滤器/空值缓存。（Day16 滚动复习）

**56. D**【RTO】RTO＝恢复时间目标（灾难到恢复运行的最长容忍），RPO＝恢复点目标（可容忍的数据丢失量）——RTO 管时间、RPO 管数据。（Day17 滚动复习）

**57. A**【ARINC 653 分区】时间分区（周期调度窗口互不侵占）＋空间分区（内存隔离）双隔离，防止一个分区故障污染其他分区——安全关键的基石机制。（Day18 滚动复习）

**58. B**【Lambda 架构】批处理层（全量高吞吐）＋速度层（实时增量），服务层合并两层数据对外——"批流双跑"是 Lambda 的身份标识。（Day19 滚动复习）

**59. D**【边缘计算价值】就近处理降低传输延迟与带宽压力，断网时可本地自治——"数据不动算力动"是其与纯云的分工逻辑。（Day20 滚动复习）

**60. C**【串联可靠度】0.99×0.99＝0.9801——串联越串越低；注意与并联冗余 1−(1−0.99)²＝0.9999 相反的方向。（Day01/21 滚动复习）

**61. B**【案例审题第一步】在题干圈出"刺激—环境—度量"三关键词再作答——质量属性分析题的第一动作是结构化拆解，不是急着写战术。（Day22 滚动复习）

**62. A**【熔断器三态】关闭（正常放行计数）→打开（超阈值快速失败）→半开（放少量探测请求试探恢复）——三态循环是熔断模式的机制核心。（Day23 滚动复习）

**63. A**【可用度计算】A＝1990/(1990＋10)＝1990/2000＝0.995＝99.5%——MTBF 与 MTTR 单位一致是计算前提。（Day04 滚动复习）

**64. D**【出境评估】向境外提供重要数据或达到规定规模的个人信息须申报出境安全评估；同机房主从、同城备份、网页展示均不构成出境。（Day25 滚动复习）

**65. B**【消息顺序性】以业务键（订单号/用户 ID）作分区键，同键消息恒入同分区、分区内严格有序——"局部有序"替代"全局有序"是工程正解。（Day23 滚动复习）

**66. D**【缓存一致性】延迟双删或订阅数据库 binlog 异步更新缓存，是"缓存—数据库"一致性的两条主流路径——只写缓存或只写库都是灾难。（Day16 滚动复习）

**67. D**【CA 作用】CA 是可信第三方：为证书主体签名背书，验证方以 CA 公钥验签即可信任证书真伪——信任链的根在 CA。（Day03/17 滚动复习）

**68. B**【湖仓一体】在数据湖低成本存储之上实现仓库级管理能力（表结构、ACID 事务、性能优化）——"湖的存储＋仓的管理"。（Day19 滚动复习）

**69. D**【RAG】检索增强生成：先检索外部知识库再交给模型生成，回答可溯源、知识可热更新——缓解大模型知识时效与幻觉问题的主流架构。（Day20 滚动复习）

**70. C**【网关 vs ESB】API 网关是轻量的流量与治理入口（去中心化倾向），ESB 是中心化重型集成总线——第二轮 SOA 的主角正是前者。（呼应本卷主题二）

**71. C**【专业英语】execution plan＝执行计划：优化器输出的访问路径（全表扫描还是用索引），SQL 调优第一步就是读懂它。

**72. D**【专业英语】covering index＝覆盖索引：查询所需列全在索引中，无需回表（without accessing the table rows）——对应中文考点第 4 题。

**73. A**【专业英语】service registry＝服务注册中心：服务注册地址、消费方动态发现——微服务与 SOA 共用的治理基础设施。

**74. B**【专业英语】API gateway：统一认证（authentication）、限流（rate limiting）、路由与监控——开放平台架构的咽喉。

**75. C**【专业英语】quota＝配额：限制每秒/每日请求数，保护平台总容量——开放平台运营术语。
